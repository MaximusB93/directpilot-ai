# ТЗ №4. Гигиена интерфейса

Полоса **B**. Ветка `feat/ui-hygiene` от `main`.

## Зачем

Шесть дефектов, из-за которых работающий продукт выглядит сломанным. Все они видны на первом же экране и разрушают доверие быстрее, чем любая неточность в рекомендациях. Ни один не требует новой логики.

## Границы задачи

**Делаем:** только `src/**` — разметка, стили, тексты.

**Не делаем в этой задаче:**

- не трогаем backend;
- не меняем форму «Контекст бизнеса» (17 полей в ряд) — это переработка формы, отдельное ТЗ;
- не меняем общую ширину контейнера страниц — отдельное ТЗ;
- не продолжаем и не откатываем незаконченный переезд `main.js` в модули страниц;
- не рефакторим CSS-файлы и не объединяем их.

Каждый пункт ниже — независимая правка. Их можно делать по одной.

## 1. Подписи слипаются со значениями

### Симптом

На пяти экранах подпись и значение выводятся без разделителя:

```
ГотовностьМожно запускать     Последний статусok
Черновики0    Одобрено0    Отклонено0    К предпросмотру0
Emailmaksim.budnikov…    Backendподключён    APIhttps://…
Нишане указана    ГеографияЭсто-Садок, Адлерский район…
```

### Причина (установлена)

По всему фронтенду используется один шаблон:

```html
<article><span>Подпись</span><strong>Значение</strong></article>
```

`span` и `strong` — строчные элементы, поэтому без CSS они встают в одну строку вплотную. Стили написаны не для самого шаблона, а для отдельных контейнеров:

| Контейнер | CSS | Результат |
|---|---|---|
| `.aiModelSummary` | есть, включая правило для `span` (`src/app-ui-final.css:717`) | отображается верно |
| `.kpi` | есть (`src/app-product-polish.css:193,199`) | отображается верно |
| `.syncStatusGrid` | **нет ни одного правила** | слипается |
| `.insightGrid` | проверить | слипается |

Всего шаблон встречается 39 раз (`grep -rn "<article><span>" src/`). Чинить каждый контейнер по отдельности не нужно и вредно — дефект вернётся с седьмым контейнером.

### Что сделать

Добавить одно базовое правило для самого шаблона, чтобы любой контейнер по умолчанию отображался верно, а существующие правила контейнеров продолжали его переопределять:

```css
body[data-page="app"] article > span + strong { display: block; }
body[data-page="app"] article > span:has(+ strong) { display: block; }
```

Селектор намеренно ограничен парой `span + strong`. Он **не должен** затрагивать:

- нумерованные карточки `<article><span>01</span><h3>…` (`src/main.js:547–549`);
- карточки рекомендаций `<article><span>приоритет</span><h3>…` (`src/pages/ai-assistant.js:623`).

Если `:has()` нежелателен, допустимо задать `display: block` только для `strong` — визуально этого достаточно, подпись останется на своей строке.

Правило разместить в том же файле, где лежат существующие правила `.kpi`, а не в новом CSS-файле. Новых файлов стилей не создавать.

### Проверка

Открыть все девять разделов и убедиться, что подпись и значение везде на разных строках, а нумерованные карточки и карточки рекомендаций выглядят как раньше.

## 2. «Обзор» показывает нули поверх реальных данных

### Симптом

На главном экране сверху: красная плашка «Backend не ответил за 25 секунд» и восемь карточек — Кампаний 0, Показы 0, Клики 0, Расход 0 ₽, CTR 0,0 %, CPC 0 ₽, Конверсии 0, CPA 0 ₽, плюс подпись «Данные за период ещё не загружены».

Сразу под этим блоком, на том же экране, лежит таблица «Сводка эффективности» с реальными числами: 139 247,89 ₽, 1 268 кликов, 22 конверсии.

### Что сделать

Нули при неуспешном или незавершённом запросе показывать нельзя — ноль это утверждение о данных, а не признак их отсутствия.

Три состояния блока «Сводка за период»:

| Состояние | Что показываем |
|---|---|
| Загрузка | скелет или прочерки `—`, не нули |
| Ошибка запроса | сообщение об ошибке и прочерки; если есть ранее загруженные данные — показать их с пометкой «данные от <дата>» |
| Успех | сами значения |

Подпись «Данные за период ещё не загружены» показывать только когда данных действительно нет — не когда запрос упал.

Дополнительно: период выводится как `2026-06-09T16:24:04.461913+03:00 — 2026-07-08T16:24:04.461913+03:00`. Привести к виду `9 июня — 8 июля 2026`.

## 3. «Оптимизация» просит нажать несуществующую кнопку

### Симптом

Раздел выводит: «План пока не сформирован. Загрузите статистику и нажмите &laquo;Обновить план&raquo;». Кнопки «Обновить план» на экране нет — есть неактивные «Формируем…» и «Сохранить как черновики». Ниже бесконечно висит «Загружаем черновики согласования…».

### Что сделать

Привести текст в соответствие с интерфейсом: назвать кнопку, которая действительно есть, либо вернуть кнопку, которая описана. Выбрать один вариант, не оставлять расхождение.

Индикатор «Загружаем черновики согласования…» должен исчезать по завершении запроса — и при успехе, и при ошибке.

## 6. Служебные коды в интерфейсе

### Симптом

По экранам разбросаны внутренние идентификаторы, которые пользователь видеть не должен:

```
direct_no_data · next_level_requested · campaign_metadata_issue
manual_review · Saved fallback · optimization.action_status_changed
audience_targets · autotargeting · campaign_daily_dynamics · frequency
retargeting_lists · campaign_settings
```

В одной таблице половина строк по-русски («устройства», «география», «цели»), половина — кодом. Плюс наружу выводится UUID привязки аккаунта и период с микросекундами.

### Что сделать

Один общий словарь соответствий «код → человеческое название» в `src/core/`, и функция перевода, применяемая во всех местах вывода.

Главное правило: **если кода нет в словаре, не выводить его вовсе** — показать прочерк или опустить строку, но не печатать сырое значение. Иначе каждый новый код бэкенда снова протечёт в интерфейс.

UUID привязки аккаунта на странице «Клиенты и интеграции» скрыть.

## Критерии приёмки

- Изменения только в `src/**`.
- `npm run build` проходит.
- Новых CSS-файлов не создано.
- Пункт 1 решён одним правилом для шаблона, а не перечислением контейнеров.
- Нигде в интерфейсе не выводится значение, которого нет в словаре из пункта 6.
- Нумерованные карточки и карточки рекомендаций выглядят как до правки.

## Ручная проверка

Пройти все девять разделов: Обзор, Диагностика, Клиенты и интеграции, Контекст бизнеса, AI-аналитик, Оптимизация, Wordstat, Журнал, Настройки. На каждом убедиться, что нет слипшихся подписей, нет сырых кодов и нет чисел, противоречащих соседнему блоку.
