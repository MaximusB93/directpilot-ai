# ТЗ №7. Экран утренней сводки

Полоса **B**. Ветка `feat/digest-screen` от `main`.

## Зачем

Сводка считается и хранится, но её никто не видит. Это половина работы: находка,
которую не показали, ничем не отличается от ненайденной.

По определению продукта главный экран — лента находок. Этот экран и есть первый её вид.

## Границы задачи

**Делаем:** только `src/**`.

**Не делаем в этой задаче:**

- не трогаем backend — endpoint готов и менять его не нужно;
- не делаем обзор по всем кабинетам сразу: `GET /clients/{id}/digest` отдаёт одного
  клиента, а сводный endpoint — отдельная задача полосы A;
- не делаем кнопку «пересчитать»: пересчёт — дело планировщика, а ручной запуск
  требует секрета, которого во фронтенде быть не должно;
- не трогаем разделы «Диагностика», «AI-аналитик», «Оптимизация».

## Где размещается

**Первым блоком на «Обзоре», выше всего остального.**

Не новая страница и не новый пункт меню. Причина: находки должны быть первым, что
видит человек, открывая продукт, а перенос навигации — отдельный риск, не связанный
с этой задачей. Существующие блоки «Обзора» съезжают ниже и не меняются.

---

## 1. Что отдаёт backend

```
GET {api_prefix}/clients/{client_id}/digest[?date=YYYY-MM-DD]
```

Ответ:

```json
{
  "client_id": "...",
  "digest_date": "2026-09-02",
  "created_at": "2026-09-03T05:30:12+00:00",
  "status": "ok",
  "findings_count": 2,
  "findings": [ ... ]
}
```

Находка:

```json
{
  "signal": "spend_spike",
  "scope": "account",
  "campaign_id": null,
  "campaign_name": null,
  "lever": "unknown",
  "evidence": {"cost_current": 9000.0, "cost_previous": 1000.0,
               "cost_absolute": 8000.0, "cost_percent": 800.0},
  "money_at_stake": 240000.0,
  "confidence": "low",
  "confirmed_by_week": true,
  "action": "Откройте кампанию и сверьте ставки…",
  "repeated": false
}
```

**Состав `evidence` разный у разных сигналов.** Это не ошибка: у скачка расхода одни
числа, у падения CTR другие. Отсюда требование раздела 4.

---

## 2. Четыре состояния экрана

Их именно четыре, и смешивать их нельзя.

| Состояние | Когда | Что показываем |
|---|---|---|
| Сводки ещё нет | ответ **404** | «Сводка за <дата> ещё не считалась» — спокойно, без красного |
| `status = "no_data"` | нет дневных данных | «Нет данных за период — запустите синхронизацию», со ссылкой на синхронизацию |
| `status = "ok"`, находок 0 | всё спокойно | **«Вчера всё спокойно»** — см. раздел 3 |
| `status = "ok"`, находки есть | обычный день | карточки находок |

**404 — не ошибка.** Планировщик мог ещё не отработать, клиента могли добавить вчера.
Красная плашка здесь была бы повторением дефекта, который чинили в ТЗ №4: сообщение
о поломке там, где ничего не сломано.

Разделение «нет сводки» / «нет данных» / «пусто» обязательно по той же причине, по
которой в backend `None` не равен нулю: это три разных факта о мире.

---

## 3. Молчание должно выглядеть намеренным

Пустая сводка — это результат, а не отсутствие результата. Пустой белый блок читается
как «сломалось».

Показываем: заголовок «Вчера всё спокойно», дату, и **что именно было проверено** —
расход, конверсии, CPA, CTR по аккаунту и по кампаниям за вчера против того же дня
недели неделю назад. Числа берутся из ответа, если они там есть; выдумывать нельзя.

Смысл: человек должен видеть, что система смотрела и не нашла, а не что она молчит,
потому что сломалась.

---

## 4. Карточка находки

Порядок сверху вниз:

1. **Деньги — крупно.** `money_at_stake`, отформатированные как рубли в месяц.
   Это то, ради чего просят внимания, и это должно читаться первым.
2. **Заголовок**: человеческое название сигнала плюс объект — название кампании
   либо «Аккаунт целиком» при `scope = "account"`.
3. **Доказательство**: числа из `evidence`.
4. **Действие**: `action`, как есть. Текст уже написан backend и переписывать его
   во фронтенде нельзя — иначе появится второй источник формулировок.
5. **Пометки**: рычаг, уверенность, подтверждение неделей, повтор.

### Названия — только через словарь

Использовать `labelFor` из `src/core/labels.js` (ТЗ №4) для `signal`, `lever`,
`confidence` и ключей `evidence`. Добавить недостающие группы в тот же словарь.

**Правило то же, что в ТЗ №4: кода, которого нет в словаре, в разметке быть не должно.**
Неизвестный ключ `evidence` пропускается, неизвестный сигнал показывается как находка
без заголовка сигнала, но с объектом, деньгами и действием — они всегда осмысленны.

Это существенно: сигналы и ключи доказательств будут добавляться на backend, и экран
не должен ни ломаться, ни печатать `cost_absolute` пользователю.

### Пометки

- **Рычаг** — чип: «пустой расход» / «цена клика» / «конверсионность» / «оба».
  При `lever = "unknown"` чип не показывается вовсе, а не показывается словом «unknown».
- **`confirmed_by_week = false`** — пометка «не подтверждено недельной динамикой».
  Скрывать нельзя: это честная оговорка о качестве вывода.
- **`repeated = true`** — приглушённая карточка и пометка «повторяется». Человек
  должен отличать новую проблему от вчерашней.
- **Уверенность** — словом, не кодом.

### Осторожно с уверенностью у денежных сигналов

У `spend_spike` уверенность сейчас считается по числу кликов, поэтому точный рост
расхода в восемь раз может быть помечен как `low`. Это известный дефект backend,
он чинится отдельной задачей (ТЗ №8).

**Во фронтенде это не обходить и не прятать.** Показывать то, что пришло. Если
подпирать чужой дефект в интерфейсе, он станет невидимым и никогда не будет исправлен.

---

## 5. Порядок и количество

Находки показывать в том порядке, в каком они пришли: backend уже отсортировал их
по деньгам по убыванию. Не пересортировывать во фронтенде — иначе появится второе
место, где решается, что важнее.

Их не больше пяти, ограничение уже применено на backend. Своего ограничения не вводить.

---

## 6. Дата и обновление

Показывать дату сводки словами через `formatDateRange` или `toLocaleDateString('ru-RU')`,
как в ТЗ №4: «2 сентября 2026», не `2026-09-02`.

Рядом — когда сводка посчитана (`created_at`), тем же способом.

Запрос выполняется при выборе клиента и при переходе на «Обзор». Отдельной кнопки
обновления не нужно.

Состояния запроса — как в ТЗ №4, пункт 2: во время загрузки прочерки или скелет,
при ошибке сети сообщение об ошибке, **но не нули и не пустая сводка**. Отсутствие
ответа не равно «всё спокойно».

---

## 7. Проверки

`npm run build` должен проходить. Если в `scripts/validate-static.mjs` есть список
обязательных файлов — новый модуль страницы добавить туда по образцу существующих.

Смоук на чистых модулях, по образцу ТЗ №4: неизвестный сигнал и неизвестный ключ
`evidence` не попадают в разметку сырыми.

### Что проверить вручную

Все четыре состояния из раздела 2. Проще всего подставить ответ вручную: временно
вернуть из сервиса заготовленный объект, посмотреть экран, вернуть как было.

Обязательно посмотреть состояние «всё спокойно» глазами и честно ответить: выглядит
ли оно как осмысленный ответ или как пустое место. Если второе — переделать.

---

## Критерии приёмки

- Изменения только в `src/**`.
- `npm run build` — зелёный.
- Ни один код (`signal`, `lever`, `confidence`, ключи `evidence`) не выводится сырым.
- 404 не показывается как ошибка.
- Четыре состояния различимы на экране и не сведены к двум.
- Текст действия выводится как пришёл, без переписывания во фронтенде.
- Порядок находок не меняется относительно ответа backend.
- Разделы «Диагностика», «AI-аналитик», «Оптимизация» и backend не изменены.

## Что дальше

Обзор по всем кабинетам сразу — та же карточка находки, но список по клиентам.
Он требует сводного endpoint на backend, поэтому это отдельная задача полосы A.
Карточку имеет смысл сразу вынести в переиспользуемую функцию отрисовки.
